# CustomerIQ Marketing Case Studies Framework

This directory stores a lightweight, structured evidence framework for the CustomerIQ marketing intelligence layer.

## Purpose

The purpose of the evidence library is to expose real-world, source-backed case-study precedents that can support transparent marketing recommendations. The library exists to answer questions such as: what strategy patterns have been observed in comparable customer contexts, and what evidence quality and limitations should be shown to a user before a recommendation is made.

## Source Quality

The library is designed to preserve source provenance. Every case study must keep its source and source URL. Evidence quality is documented as a qualitative measure such as Low, Medium, or Medium-high rather than being treated as proof that a recommendation will work.

## Matching Logic

Cases are matched by transparent signals such as HIGH RISK + HIGH VALUE, LONG RECENCY, DECLINING USAGE, CANCELLATION INTENT, or PRODUCT / CONTENT AFFINITY. Matching is separate from prediction and should never create a causal claim.

## Why Cases Are Not ML Training Data

The case-study library is not used for churn prediction training. It is a separate evidence and reasoning layer used only to enrich the CustomerIQ marketing intelligence output. CustomerIQ prediction remains a model-driven risk estimate; the case-study layer is a human-readable, source-aware precedent layer.

## Difference Between Prediction and Recommendation

Prediction = churn probability and risk segment generated by the CustomerIQ model and behavioral features.
Recommendation = a potential strategy generated from the marketing intelligence service using risk, behavioral signals, revenue exposure, and relevant evidence.
A case study is a factual or descriptive precedent, not proof that a recommendation will work.

## Limitations

The evidence layer cannot establish causality. It should be used to explain a possible strategy pattern and to surface evidence-backed reasoning. CustomerIQ should continue to apply holdout/control-group validation before scaling any recommendation.

## How Future Cases Can Be Added

A future case can be added to the structured evidence library by extending the case-study schema and preserving:

- company
- industry
- customer_problem
- observed_signals
- target_segment
- intervention
- strategy
- channels
- reported_outcome
- evidence_quality
- source
- source_url
- limitations
- customeriq_signal_mapping
- applicability_conditions

No fabricated evidence or unsupported statistics should be added. All cases must stay separate from the ML model and from training data.
